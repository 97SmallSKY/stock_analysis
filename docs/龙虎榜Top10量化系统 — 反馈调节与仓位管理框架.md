## 一、问题诊断：现有熔断机制的根本缺陷

### 1.1 当前实现（代码现状）

`check_circuit_breaker()` 已在 `sim_trade_db.py` 落地，触发逻辑为：

| 规则 | 条件 | 行为 |
|------|------|------|
| 单日熔断 | 今日亏损 > -3% | `allow_open=False`，当日停止开仓 |
| 连续亏损熔断 | 连续亏损 ≥ 3 笔 | `allow_open=False`，跳过今日开仓 |
| 周亏损熔断 | 本周亏损 > -5% | `allow_open=False`，本周剩余停止 |
| 月回撤熔断 | 本月亏损 > -8% | `allow_open=False`，本月剩余停止 |
| 最大回撤熔断 | 近10笔最大回撤 > -15% | `allow_open=False`，建议清仓 |
| AHS 极低预警 | AHS < 30 | `allow_open=True`，level=warning，仓位压缩 |

**已有的优点：**
- 熔断逻辑已完整落地，五层防护
- AHS 评分体系已联动，数据不足时默认中性值 60
- 支持环境变量 `SKIP_CIRCUIT_BREAKER=1` 人工覆盖

### 1.2 核心问题：**急刹车 vs 降速行驶**

```
当前逻辑：
  连亏3笔 → allow_open=False → 今日全部停止开仓

问题：
  场景1: 周一连亏3笔进入熔断
         周二龙虎榜出现90分顶级信号
         → 系统拒绝开仓
         → 错过机会，且错误归因（亏损可能是大盘系统性原因）

  场景2: 亏损原因是"选股质量差（评分50的票也做了）"
         → 正确应对是提高入场门槛
         → 但现有系统直接"停车"，无法区分原因

  场景3: 周度熔断触发
         → 本周剩余3天全部空仓
         → 若大盘此时转折放量上涨，往往是最好的龙虎榜机会
```

**核心认知：** 把"降低风险"等同于"停止交易"是错的。正确做法是：**限速（缩仓+提高门槛），而不是停车（完全停止）**。

## 二、分级降速框架（目标架构）

### 2.1 四档运行模式

取代当前"二元熔断（开/停）"，改为**四档连续降速**：

| 模式 | 仓位系数 | 入场评分门槛 | 每日最多建仓 | 允许加仓 | 对应颜色 |
|------|---------|------------|------------|--------|--------|
| **正常模式** | 100% | 50 分 | 5 只/天 | ✅ | 🟢 绿 |
| **谨慎模式** | 70% | 60 分 | 3 只/天 | ✅ | 🟡 黄 |
| **警戒模式** | 40% | 70 分 | 1 只/天 | ❌ | 🟠 橙 |
| **危机模式** | 20% | 80 分 | 1 只/天 | ❌ | 🔴 红 |

**关键设计：即使在危机模式（20%仓位），80分以上顶级信号仍然可以参与。**  
风险被控制，但机会不被完全封死。

### 2.2 模式升级触发条件（变严）

| 变化 | 触发条件 |
|------|---------|
| 正常 → 谨慎 | 连亏3笔 OR 单日亏损 > -2% OR 周亏损 > -3% |
| 谨慎 → 警戒 | 连亏5笔 OR 周亏损 > -5% OR AHS < 45 |
| 警戒 → 危机 | 连亏7笔 OR 月亏损 > -8% OR 近10笔最大回撤 > -12% |

### 2.3 模式恢复触发条件（变宽）——关键改进

**不是固定等待天数，而是根据条件动态恢复：**

| 恢复条件 | 效果 | 说明 |
|---------|------|------|
| 连赢 2 笔 | 自动升一级（变宽松） | 策略重新有效，证据充分 |
| 大盘从下跌转上涨（MA5 上穿 MA20） | 自动升一级 | 系统性原因消除 |
| 出现 85 分以上顶级信号 | 允许以当前仓位系数×1.5 参与（但不超过正常上限） | 不因熔断错过最好机会 |
| 完成一次人工复盘并确认原因 | 允许手动升一级 | 人工介入的安全出口 |

**示例对比：**
```
场景: 周一连亏5笔 → 进入警戒模式（仓位40%，门槛70分）

旧方案（熔断停车）:
  周二到周五全部不交易 → 周三大盘反转暴涨，错过最好机会

新方案（分级降速）:
  周二: 仍可交易，只做70分以上信号，仓位40%
  周三: 大盘反转，出现88分信号 → 买入（仓位40%×1.5=60%，上限内）
  周三/四: 连赢2笔 → 自动恢复至谨慎模式（仓位70%）
```

## 三、亏损原因归类与差异化应对

### 3.1 为什么要区分原因

**同样的结果（连亏3笔），应对方式可能完全不同：**

```
原因A: 大盘暴跌 -5%，持仓全部被动亏损
  → 问题不在策略，在市场环境
  → 正确应对: 适度缩仓，盯大盘转折，不提高入场门槛
  → 错误应对: 提高门槛至70分（会错过大盘反弹时的好信号）

原因B: 买了50分低质量信号亏损
  → 问题在入场标准太松
  → 正确应对: 提高入场门槛，仓位不需要大幅缩减
  → 错误应对: 缩到20%仓位但门槛不变（量少了但质没提高）

原因C: 止损太晚，每笔亏损额度大
  → 问题在出场机制
  → 正确应对: 收紧止损线（如从-7%→-5%），不需要减少交易次数
  → 错误应对: 停止交易（治标不治本）

原因D: 策略整体失效，连续30笔胜率<35%
  → 最严重的情况
  → 正确应对: 大幅缩仓+人工介入复盘，可能需要修改策略
  → 不能靠自动机制解决
```

### 3.2 自动识别亏损原因的方法

| 亏损原因 | 自动识别规则 | 记录字段 |
|---------|------------|---------|
| 大盘系统性下跌 | 当日大盘跌幅 > -2% 且 当日持仓中 ≥ 70% 同步亏损 | `loss_reason = "market_systemic"` |
| 选股质量差 | 亏损交易的入场评分集中在 < 60 分区间 | `loss_reason = "low_quality_signal"` |
| 止损执行太晚 | 单笔亏损 > -8% 的比例 > 30% | `loss_reason = "late_stop_loss"` |
| 策略整体失效 | 近30笔胜率 < 35% 且近10笔 IC 全面下降 | `loss_reason = "strategy_decay"` |
| 未识别 | 不满足上述任一条件 | `loss_reason = "unknown"` |

### 3.3 不同原因对应的调参方向

```
原因: market_systemic（大盘导致）
  调整: 仓位系数 × 0.7（缩仓），但入场门槛不变
  恢复: 大盘MA5上穿MA20时自动恢复

原因: low_quality_signal（低质入场）
  调整: 入场门槛 +10分，仓位系数不变
  恢复: 连续2笔高分信号（>70分）盈利后自动恢复门槛

原因: late_stop_loss（止损太晚）
  调整: 止损线收紧 1%（如 -7% → -6%），不减少交易次数
  恢复: 连续5笔单笔亏损均未超过新止损线，恢复原止损线

原因: strategy_decay（策略失效）
  调整: 进入危机模式（仓位20%，门槛80分），触发人工复盘告警
  恢复: 仅允许人工介入后手动恢复（不自动）
```

## 四、AHS 评分与仓位联动的完整映射

### 4.1 现有 AHS 评分构成

`calc_account_health_score()` 当前实现（`sim_trade_db.py` L1894）：

| 维度 | 满分 | 计算方式 |
|------|------|---------|
| 基础分 | 50 | 固定基础 |
| 近10笔胜率 | ±25 | ≥70%→+25；60~70%→+15；50~60%→+5；40~50%→-5；30~40%→-15；<30%→-25 |
| 近10笔平均盈亏 | ±15 | >2%→+15；>1%→+10；>0%→+5；>-1%→-5；>-2%→-10；≤-2%→-15 |
| 连续亏损惩罚 | 最多-20 | 1笔→0；2笔→-5；3笔→-10；4笔+→-20 |
| 今日盈亏修正 | ±10 | >+1%→+10；0~1%→+5；-1~0%→-5；<-1%→-10 |

### 4.2 AHS → 仓位系数映射（目标扩展）

当前代码中 AHS 只做两档 warning（<30，<45），仓位联动尚不够精细。**目标映射表：**

| AHS 范围 | 运行模式 | 仓位系数 | 入场门槛 | 说明 |
|---------|---------|---------|---------|------|
| 80~100 | 正常 | 100% | 50 分 | 策略表现优秀 |
| 65~79 | 正常 | 90% | 50 分 | 轻微保守 |
| 50~64 | 谨慎 | 70% | 60 分 | 进入修复期 |
| 35~49 | 警戒 | 40% | 70 分 | 明显回撤中 |
| 0~34 | 危机 | 20% | 80 分 | 严重修复期 |

**单笔资金上限（不受 AHS 影响的绝对限制）：**
- 单只持仓 ≤ 总资金的 **12%**
- 同一板块总暴露 ≤ 总资金的 **30%**
- 总仓位上限 ≤ 总资金的 **80%**（永远保留 20% 现金）
- 每日新建仓上限：正常5只 / 谨慎3只 / 警戒1只 / 危机1只

### 4.3 仓位计算公式

```python
def calc_position_size(
    score: int,          # 信号评分（0-100）
    ahs: int,            # 账户健康评分（0-100）
    mode: str,           # "normal" / "cautious" / "alert" / "crisis"
    total_capital: float = 100_000,
) -> float:
    """
    返回本次建仓金额（元）。

    基础仓位 = 总资金 × 10%（单笔基准）
    评分加成 = 若 score >= 75: ×1.2；若 score >= 85: ×1.5
    模式系数 = {normal: 1.0, cautious: 0.7, alert: 0.4, crisis: 0.2}
    上限约束 = min(result, total_capital × 0.12)  # 单只不超过12%
    """
    base = total_capital * 0.10
    score_multiplier = 1.5 if score >= 85 else (1.2 if score >= 75 else 1.0)
    mode_coef = {"normal": 1.0, "cautious": 0.7, "alert": 0.4, "crisis": 0.2}
    result = base * score_multiplier * mode_coef.get(mode, 1.0)
    return min(result, total_capital * 0.12)
```

### 5.1 现有实现（代码锚点）

`modules/data_fetcher.py` L860 附近有市场情绪仓位系数逻辑：

- 大盘 MA5 < MA20（空头趋势）→ 降低仓位

### 5.2 目标：AHS + 市场环境 双维度仓位决策矩阵

```
                  市场温度
                冷淡    正常    热度
      危机    15%     20%    20%
AHS   警戒    30%     40%    40%
      谨慎    50%     70%    70%
      正常    70%     90%   100%
```

**规则：** 最终仓位 = `min(AHS对应系数, 市场对应系数)`，取两个维度中的较小值。

### 5.3 大盘联动的仓位上限

```python
# 基于大盘均线关系动态调整最高仓位上限
def get_market_max_position(ma5: float, ma20: float, ma60: float) -> float:
    if ma5 > ma20 > ma60:       # 多头排列
        return 0.80
    elif ma5 > ma20:            # MA5 在 MA20 之上
        return 0.70
    elif ma5 < ma20:            # MA5 跌破 MA20
        return 0.50
    elif ma5 < ma60:            # MA5 跌破 MA60
        return 0.30
    else:
        return 0.60
```

## 六、教训管理轻量化落地方案

### 6.1 为什么需要教训管理

当前系统的复盘是**统计型**的（看后视镜）：统计胜率、报告异常。

缺少的是**认知型**复盘：
- 这笔亏损属于哪类错误？之前犯过吗？
- 上次的修复措施有没有生效？
- 如何从机制上防止再犯？

### 6.2 教训分类体系（5大类）

| 大类 | 子类 | 典型表现 |
|------|------|---------|
| **入场错误** | 追高买入 | 高开 > 5% 仍然买入 |
| | 低质信号 | 评分 < 55 就入场 |
| | 逆势/高潮期买入 | 板块已连涨 4+ 天仍新建仓 |
| | 流动性陷阱 | 日均成交额 < 5000 万的股票 |
| **出场错误** | 止损太晚 | 触及-7%止损线但拖到-12%才卖 |
| | 止盈太早 | 浮盈 3% 就跑，后续涨 15% |
| | 浮盈回吐 | 最高盈利 9%，回落到 2% 才出 |
| | 涨跌停困境 | 跌停排队卖不出 |
| **仓位错误** | 单只过重 | 一只股票占 > 12% 总资金 |
| | 板块集中 | 同板块占 > 30% |
| | 满仓遇系统性下跌 | 现金低于 20% 时遭遇大跌 |
| **系统错误** | 数据错误 | 脏数据导致错误决策 |
| | 执行延迟 | 止损信号产生但执行晚了 |
| **认知错误** | 覆盖止损 | 手动取消系统止损单 |
| | 冲动交易 | 未经系统推荐手动买入 |

### 6.3 教训的生命周期（四阶段）

```
阶段1: 发现（Day 0）
  触发: 亏损交易结束 → 自动匹配分类
  输出: 创建教训条目（ID、类别、描述、涉及交易、损失金额）

阶段2: 理解（Day 1-7）
  触发: 人工复盘 / 系统根因分析
  输出: 根因识别 + 修复方案设计（量化为可执行规则）

阶段3: 实施（Day 7-14）
  触发: 确认修复方案后编码
  形式: Level1（参数调整，自动）/ Level2（逻辑调整，确认）/ Level3（架构调整，人工）

阶段4: 验证（Day 14-45）
  标准: 30天内同类错误频次下降 ≥ 80%
  结果: 完全消化 ✅ / 消化失败（重新分析根因）
```

### 6.4 教训→规则的转化公式

```
模糊教训: "要注意板块高潮期"
             ↓
量化转化: 触发条件 + 具体动作 + 适用边界
             ↓
执行规则: "板块连涨 ≥ 3天 且 该板块当日涨停股 ≥ 5只
           → 该板块龙虎榜信号评分 -12
           → 仅作用于新建仓判断，持仓不受影响"
```

### 6.5 规则分级（决定编码位置）

| 级别 | 触发条件 | 形式 | 是否可覆盖 |
|------|---------|------|----------|
| A 级规则 | 同类错误 ≥ 3 次，每次额外亏损 ≥ 2% | 写入代码自动执行 | 否 |
| B 级规则 | 同类错误 1-2 次，或影响不确定 | 盘前检查清单（人工过） | 是 |
| C 级认知 | 偶发事件，无法量化 | 仅记录在文档，不编码 | — |

### 6.6 防止"知道但做不到"：摩擦成本设计

不完全禁止人工覆盖，但让覆盖变得"麻烦"：

| 覆盖难度 | 触发场景 | 摩擦形式 |
|---------|---------|---------|
| Level 1 | 低严重度教训 | 弹出提示，点确认跳过（1 秒） |
| Level 2 | 中严重度教训 | 必须输入覆盖原因（≥ 20 字，30 秒） |
| Level 3 | 高严重度教训 | 输入原因 + 5 分钟冷静期 |
| Level 4 | 致命规则（止损） | 代码层面不可覆盖 |

每次人工覆盖自动记录，月底汇总：  
**"本月覆盖 N 次，其中 X 次覆盖后亏损"** → 用数据说服自己系统更对。

## 七、持续进化飞轮

### 7.1 完整闭环

```
① 执行交易
        ↓
② 结果产生（盈利/亏损）
        ↓
③ 自动归因（匹配教训库 + 亏损原因4分类）
   ├─ 已知错误 → 检查拦截是否失效
   └─ 未知错误 → 创建新教训条目
        ↓
④ 根因分析（参数/逻辑/机制/战略 四级）
        ↓
⑤ 修复实施（Level1自动 → Level2确认 → Level3人工）
        ↓
⑥ 影子模式验证（2周，虚拟跑，不实际下单）
        ↓
⑦ 效果验证（30天同类错误频次下降 ≥ 80% → 完全消化）
        ↓
回到① 继续交易，策略进化一圈
```

**理想节奏：** 每 2~4 周完成一轮小循环（单个教训的完整处理）；每季度完成一次系统性审视。

### 7.2 教训消化健康度指标

| 指标 | 目标值 | 说明 |
|------|------|------|
| 教训消化率 | > 60% | 完全消化条数 / 总条数 |
| 复发率 | < 15% | 已修复教训重新出现的比例 |
| 误拦截率 | < 20% | 拦截后发现其实应该执行的比例 |
| 覆盖正确率 | < 30% | 人工覆盖后结果为盈利的比例（越低说明越应信任系统） |
| 月度新增教训 | 3~8 条 | 过多=系统有重大问题，过少=没认真复盘 |

## 九、关键认知总结

### 9.1 三个不能违背的原则

```
原则1: 止损线是硬规则，任何理由都不能取消
       写死在代码里，没有"再等等"的确认环节

原则2: 熔断≠停车，熔断=降速
       即使在危机模式，80分以上的信号仍然可以参与
       只是仓位缩到20%，风险被控制了

原则3: 人工覆盖必须留记录
       每次覆盖必须输入原因，月底汇总数据
       用数据证明：系统决策比人工决策更准确
```

### 9.2 资金管理的数学真相

亏损后回本需要的收益率（**不对称性**）：

| 亏损幅度 | 回本需要赚 | 难度评估 |
|---------|---------|---------|
| -5% | +5.3% | 容易 |
| -10% | +11.1% | 还行 |
| -20% | +25.0% | 困难 |
| -30% | +42.9% | 很难 |
| -50% | +100.0% | 几乎不可能 |

**结论：** 防守（止损 + 仓位控制）比进攻（选股）更重要。  
严格止损一次，节省的不只是这笔钱，而是未来5~10笔回本交易的成本。

### 9.3 系统与人性的分工

```
系统负责：
  - 止损执行（硬规则，不经人工确认）
  - 仓位计算（AHS + 市场环境双维度）
  - 熔断检查（四层防护，自动降速）
  - 教训拦截（盘前提醒 + 实时拦截）

人负责：
  - 月度策略方向审视
  - 教训根因的深度分析
  - 新因子/新策略的设计与验证
  - 极端情况下的战略判断（策略整体失效时）

人不负责：
  - 单笔交易的止损执行
  - 当日是否开仓（由熔断规则决定）
  - 仓位大小（由 AHS 计算决定）
```
