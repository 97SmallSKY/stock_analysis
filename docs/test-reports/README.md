# 测试报告文档说明

> **文件夹用途**: 集中管理龙虎榜量化交易系统 v2 各阶段的测试报告文档

---

## 📁 文件夹说明

本文件夹 `docs/test-reports/` 用于存放系统开发各阶段（S01-S06）的测试报告及相关文档，包括：

- **测试摘要** - 简明测试结果总结
- **问题清单** - 待修复问题追踪
- **详细测试报告** - 完整测试执行记录（可选）
- **测试数据** - 测试用例和数据集（可选）

---

## 📝 文档命名规范

### 必需文档

每个开发阶段测试完成后，需产出以下两份文档：

| 文档类型 | 命名格式 | 示例 | 说明 |
|---------|---------|------|------|
| **测试摘要** | `S{XX}_TEST_SUMMARY.md` | `S01_TEST_SUMMARY.md` | 测试结果概览、通过率、关键发现 |
| **问题清单** | `S{XX}_ISSUES.md` | `S01_ISSUES.md` | 待修复问题列表、优先级、修复计划 |

### 可选文档

根据需要可以添加：

| 文档类型 | 命名格式 | 示例 | 说明 |
|---------|---------|------|------|
| **详细测试报告** | `S{XX}_TEST_REPORT_{DATE}.md` | `S01_TEST_REPORT_20260417.md` | 完整测试日志、截图、数据 |
| **测试计划** | `S{XX}_TEST_PLAN.md` | `S02_TEST_PLAN.md` | 测试策略、范围、资源 |
| **测试数据集** | `S{XX}_test_data/` | `S01_test_data/` | 测试用的 CSV、JSON 等数据文件 |

## 📌 注意事项

### 文档存放位置规范

⚠️ **重要**: 所有测试报告文档**必须**存放在 `docs/test-reports/` 文件夹下，不要散落在其他位置。

### 文档更新频率

- **测试摘要**: 测试完成后创建，重大问题修复后更新
- **问题清单**: 每日更新（如果有问题修复或新增）
- **详细报告**: 按需创建，通常用于重要里程碑或关键问题分析

### 问题追踪

问题清单中的每个 Issue 应该包含：
1. 清晰的问题描述（能重现）
2. 修复任务列表（可追踪）
3. 验证方法（可验证）
4. 状态和负责人（可跟进）

### Git 提交规范

提交测试报告时，建议使用以下 commit message 格式：

```bash
# 添加测试报告
git add docs/test-reports/S01_*
git commit -m "test(S01): add data layer test reports"

# 更新问题清单
git commit -m "test(S01): update issues - fixed P0 #1"

# 修复问题后更新
git commit -m "fix(S01): resolve LhbCollector field mapping issue #1"
```
