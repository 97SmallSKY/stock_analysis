> 设计日期: 2026-04-02
> 关联文档: [复盘总结系统增强设计方案.md](./复盘总结系统增强设计方案.md)

## 一、背景与目标

现有复盘系统已覆盖：亏损归因、交易教训双写、LLM 闭环消费。

**本模块解决两个核心缺失：**

1. **横向对比**：同一天龙虎榜 Top10 里，没选的股票后来表现如何？为什么没选它？评分体系是否存在系统性偏差？
2. **纵向事件**：持股期间发生了什么关键事件（机构席位增减、新闻利好/利空、技术指标突破、连板高度变化）？

**设计原则：**
- 数据层合并（复用 `sim_selection_log` 现有数据，避免重复存储）
- UI 独立（新建 `pages/trade_comparison.py` 专属页面）
- 新闻事件接入 AKShare `stock_news_em`（东方财富），LLM 仅对高价值案例触发
- 输出：结构化表格 + 高价值案例（错失>5%或止损单）LLM 深度分析

## 二、数据架构

### 2.1 复用现有表

**`sim_selection_log`**（已有）：记录每天所有候选股（含 rank=1 入选、rank≥2 未选）

| 字段 | 含义 |
|------|------|
| rank | 1=入选，2=次优，3=第三候选 |
| signal_score | 综合评分（0-100） |
| llm_rank_reason | LLM 对该股的排名理由（含与其他候选对比） |
| trade_id | 仅入选股有值，候选股为 NULL |

### 2.2 新增表

#### 表1: `sim_candidate_results`
补全 sim_selection_log 里候选股的 T+N 实际收益（每日 daily_update 自动填充）：

```sql
CREATE TABLE sim_candidate_results (
    id              SERIAL PRIMARY KEY,
    selection_id    INT NOT NULL,       -- FK → sim_selection_log.id
    trade_date      VARCHAR(8),
    code            VARCHAR(6),
    t1_ret          FLOAT,             -- T+1 收益%（相对 T 日收盘）
    t3_ret          FLOAT,             -- T+3 收益%
    t5_ret          FLOAT,             -- T+5 收益%
    t10_ret         FLOAT,             -- T+10 收益%
    t1_close        FLOAT,             -- T+1 收盘价
    t5_close        FLOAT,             -- T+5 收盘价
    fetched_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_cand_results_date ON sim_candidate_results(trade_date);
CREATE INDEX idx_cand_results_sel ON sim_candidate_results(selection_id);
```

#### 表2: `sim_post_tracking`
平仓后跟踪（T+1/T+3/T+5/T+10/T+15 各节点）：

```sql
CREATE TABLE sim_post_tracking (
    id           SERIAL PRIMARY KEY,
    trade_id     INT NOT NULL,           -- FK → sim_trades.id
    track_day    INT,                    -- N: 1/3/5/10/15
    track_date   VARCHAR(8),            -- 实际日期（跳过非交易日）
    close        FLOAT,
    high         FLOAT,
    low          FLOAT,
    volume_ratio FLOAT,                 -- 成交量/5日均量
    pct_vs_sell  FLOAT,                 -- 相对卖出价涨跌幅 %
    pct_vs_buy   FLOAT,                 -- 相对买入价涨跌幅 %
    index_pct    FLOAT,                 -- 上证指数当日涨跌幅 %
    created_at   TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(trade_id, track_day)
);
```

#### 表3: `sim_news_events`
持股期间新闻事件（AKShare `stock_news_em` 拉取，LLM 分类）：

```sql
CREATE TABLE sim_news_events (
    id          SERIAL PRIMARY KEY,
    trade_id    INT NOT NULL,
    code        VARCHAR(6),
    event_date  VARCHAR(8),
    title       TEXT,
    url         TEXT,
    sentiment   VARCHAR(8),            -- positive / negative / neutral
    keywords    TEXT,                  -- JSON array，如 ["机构增持", "业绩超预期"]
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_news_trade ON sim_news_events(trade_id);
CREATE INDEX idx_news_date ON sim_news_events(event_date);
```

## 三、核心模块

### 3.1 `modules/post_close_tracker.py`

**职责**：平仓后采集 T+N 价格数据，写入 `sim_post_tracking`

```python
def track_post_close(trade_id: int) -> bool:
    """
    对单笔已平仓交易，采集平仓后 T+1/T+3/T+5/T+10/T+15 价格
    使用 market_data.get_kline() 拉取 K 线
    幂等操作（UNIQUE 约束保护重复写入）
    """

def batch_track_pending() -> int:
    """
    批量处理所有 status='closed' 但 sim_post_tracking 记录不完整的交易
    在 daily_update step9 中调用
    返回处理笔数
    """
```

**数据流**：
```
sim_trades (status=closed) → 找到所有未完成跟踪记录
  → market_data.get_kline(code, sell_date, sell_date+15)
  → 计算 pct_vs_sell / pct_vs_buy / volume_ratio / index_pct
  → INSERT INTO sim_post_tracking (幂等)
```

### 3.2 `modules/news_fetcher.py`

**职责**：拉取持股期间东方财富个股新闻，LLM 分类情感

```python
def fetch_news_during_hold(code: str, buy_date: str, sell_date: str) -> pd.DataFrame:
    """
    调用 ak.stock_news_em(symbol=code) via safe_akshare_call
    过滤时间范围（buy_date ≤ publish_time ≤ sell_date）
    返回 DataFrame: title / publish_time / url
    """

def classify_news_sentiment(news_df: pd.DataFrame, trade_id: int) -> None:
    """
    调用 Claude API (claude-haiku-4-5) 批量分类情感 + 提取关键词
    仅对高价值案例触发：
      - sell_type = '止损' OR
      - 同天有候选股 T+5 收益 > 5%（错失机会）
    写入 sim_news_events 表
    """
```

**触发时机**：平仓时（`sim_trade_db.close_trade`）异步触发，不阻断主流程

### 3.3 `modules/comparison_analyzer.py`

**职责**：核心对比逻辑

```python
def build_comparison_table(trade_date: str) -> pd.DataFrame:
    """
    生成同天候选对比表：
    代码 / 名称 / 评分 / 评分排名 / T+5收益 / 收益排名 /
    是否买入 / 评分vs收益差距 / 未选主因 / 后续是否再上龙虎榜

    数据来源：
      - sim_selection_log（评分、排名、原因）
      - sim_candidate_results（T+N 收益）
    """

def find_missed_opportunities(
    start_date: str, end_date: str, threshold: float = 5.0
) -> pd.DataFrame:
    """
    在日期范围内，找出所有错失机会（未买入股 T+5 收益 > threshold%）
    按错失收益降序排列，用于周报和 Tab3 统计
    """

def analyze_same_day_candidates(trade_date: str) -> dict:
    """
    返回同天汇总分析：
    - 最优选择（实际收益最高的股票）
    - 是否选中最优（入选股是否就是收益最高的）
    - 评分与收益的相关性（斯皮尔曼秩相关）
    - 未选最优股的原因摘要
    """

def get_holding_timeline(trade_id: int) -> dict:
    """
    持股时间轴：每天价格变动 + 当天新闻事件 + 技术信号变化
    数据来源：sim_price_log + sim_news_events + sim_post_tracking
    """

def generate_llm_deep_analysis(trade_id: int) -> str:
    """
    高价值案例（错失>5% 或止损单）触发 LLM 深度分析：
    - 为什么没选最优股（评分维度对比）
    - 评分体系哪个权重需要调整
    - 持股期间关键事件的影响
    """
```

## 四、UI 模块

### 4.1 新建 `pages/trade_comparison.py`

**三个 Tab：**

**Tab1：同天候选对比**
- 日期选择器 → 加载当天所有候选股
- 散点图：X轴=评分，Y轴=T+5收益，颜色区分已买入/未买入，标注最优选择
- 结构化对比表（可排序、可筛选）
- 汇总指标：评分与收益相关性、是否选中最优

**Tab2：单次交易深度复盘**
- 从已平仓交易列表选择一笔
- K线图（持仓期间 + 平仓后T+15），事件标注点（新闻、机构席位变动）
- 同天其他候选收益对比柱状图（高亮持有股）
- 反事实分析表：如果持有到 T+5/T+10/T+15 会如何
- LLM 深度分析文字（仅高价值案例，可手动触发）

**Tab3：错失机会统计**
- 日期范围选择 → 最大错失机会 Top10 表
- 评分体系偏差分析：哪类特征的股票经常被低估
- 改进建议（基于统计规律，非 LLM）

## 五、数据流与触发时机

```
每日 daily_update（新增 step9/step10）
  step9:  batch_track_pending()   → 填充 sim_post_tracking
  step10: fill_candidate_returns() → 填充 sim_candidate_results T+N 收益

T+1 开盘买入完成后
  → 立即触发 step10 的 T+1 收益填充（其余 T+N 后续补全）

平仓时（sim_trade_db.close_trade 末尾，异步、不阻断）
  → fetch_news_during_hold(code, buy_date, sell_date)
  → 判断是否高价值案例 → classify_news_sentiment()

周五 summary_report.generate_weekly_report()
  → 调用 find_missed_opportunities(本周日期范围)
  → 生成「本周选股复盘」区块追加到飞书日报
```

## 七、待办与已知问题

### 待验证
1. **Excel 模式兼容性**：当前新增的3个表和 CRUD 函数均依赖 PostgreSQL（`_get_engine()`）。若 `STORAGE_MODE="excel"` 时调用会报错。需要在 `comparison_analyzer.py` 和 `post_close_tracker.py` 的入口处加 `storage_mode` 检查（参考 `utils/storage.py` 现有模式判断逻辑）。

2. **`sim_candidate_results` 缺 UNIQUE 约束**：当前 `save_candidate_results` 用 `ON CONFLICT DO NOTHING`，但表定义未加 UNIQUE(selection_id)，会导致 `ON CONFLICT` 无效。需要在建表 DDL 中加 `UNIQUE(selection_id)`。

3. **`get_kline_raw` 参数**：`post_close_tracker.py` 中调用 `get_kline_raw(code, sell_date, days=0)` 是为了取 sell_date 之前的数据，但 `get_kline_raw` 的 `days` 参数是窗口大小，`days=0` 可能返回空。应改为 `days=10` 并手动截断到 `sell_date`。

### 下一步建议
- 运行 `python -c "from skills.stock_sim_robot.sim_trade_db import create_extended_tables; create_extended_tables()"` 建表
- 运行 `python scripts/daily_update.py --steps 10` 填充历史候选股收益
- 启动 Streamlit 查看新页面 `pages/trade_comparison.py`
