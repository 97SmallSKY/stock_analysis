## 📚 真实案例(给未来 PM 学习)

### 案例 1(L4 · 钱类)· STO-31 北交所 920* 股票无数据源

**背景**:3 方案 A/B/C。A 花钱升级 Tushare 2000 元/年;B 开发东财接口(有封 IP 风险);C 标记 is_active=false 放弃 307 只股票。

**PM 判决**:选 C(免费可逆方案),转 `@dev`。

**理由**:
- 按「钱类选免费方案」规则,A 先排除
- B 免费但不稳定 + 开发成本高
- C 可逆(一条 SQL 恢复),风险最低

**评论留痕**:「未来如想升级 A,直接回本 issue 评论『升级方案 A』重新打开」

### 案例 2(L2 · 技术实现)· STO-32 sentiment_change 总返回 0

**背景**:可能是数据问题(回填算法粗糙)或逻辑问题(算法本身)。

**PM 判决**:让 @dev 先跑 SQL 查分布,按结果自己分支选修法,**PM 不等 @dev 结果**。

**理由**:
- 两种分支都是常规技术实现,不涉及钱/不可逆/外部依赖
- 多一次交接浪费时间
- Dev 有足够能力按 SQL 结果选择

**评论留痕**:
```
- 若 stddev < 2 或 unique_scores < 10 → 改评分公式
- 若 stddev >= 2 → 修逻辑 bug
```

### 案例 3(L2 · 产品小事)· STO-36 空态 CTA 跳向

**背景**:Robots / BacktestRun 两页空态加 CTA,3 个跳向待定。

**PM 判决**:全部选最稳默认方案,**不问用户**。

**理由**:
- 复用现有 Modal / 锚点定位,不新建页 / 不写新文档
- 实现成本最低
- 若未来有更好方案,follow-up issue 迁移即可

**方案**:
- Robots CTA → 复用页面顶部「新建机器人」Modal
- BacktestRun CTA → 锚点定位到本页表单
- 帮助链接 → `docs/CHANGELOG.md`(已在前端「特性介绍」tab)

用于:STO-36 类

## 📌 什么时候必须升级(L4)而不能 PM 自己定

- 需要花钱(买服务 / 升级订阅 / 购买数据)
- 操作不可逆(删表 / 物理删除历史数据 / 关闭线上功能无法恢复)
- 外部依赖(签第三方合同 / 依赖用户授权 / 依赖你本人的账号信息)

这三类如果 PM 自己决定,**哪怕技术上能实现,也可能给你造成实际损失**。
