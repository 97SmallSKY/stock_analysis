                   │ git push → origin
                   ▼

│ 系统环境                                                 │
│   - 出站默认走 SG 代理 (env HTTP_PROXY/HTTPS_PROXY)       │
│   - 国内源 (akshare/sina/eastmoney) 需在 adapter 内绕过   │
│                                                          │
│ 服务                                                     │
│   ┌ nginx :80/443  ── reverse proxy                      │
│   ├ FastAPI :8000  ── REST + WebSocket                   │
│   ├ Celery workers ── 回测 / 数据同步 / 报表              │
│   ├ APScheduler    ── 日终批 / 盘中 10s / 健康检查        │

└──────────────────────────────────────────────────────────┘

**理由**
- 和用户既有工作流（`ssh jd "git pull"`）完全一致，无需引入 RPC/网关。
- AKShare 在 jd 执行不会被封 IP；本地执行会被封，因此本地不做联调。
- 数据库本地化访问，免去跨网络延迟与公网暴露风险。

## 4. 数据网关层 (Data Gateway) 详细设计

### 4.1 适配器 (Adapter)

- `BaseDataAdapter`（已实现）保留：生命周期、令牌桶限流、`health_check()`、按品类的 `get_xxx()` 方法。
- 每个 adapter 维护：
  - `_supported_categories: set[DataCategory]`  → Router 跳过不支持的链节点。
  - `_session: requests.Session`  → 在 `__init__` 里按 **代理策略 (§5)** 注入。
  - `_circuit_breaker: CircuitBreaker`  → 已有。

**TuShare adapter v2**：
```python
_supported_categories = {DataCategory.DAILY_KLINE}
# 其他方法统一 raise NotSupportedByAdapter
# 预留注释：# TODO(2000积分): 恢复 FINANCIAL_DATA / INDEX_DAILY / STOCK_INFO
```

### 4.2 Router

- 保持现有 `DataRouter.fetch(category, **kwargs)` 入口。
- 补全调用 **CircuitBreaker.allow_request()** 的判断（当前骨架缺失，必须在 fetch 循环里加）。
- 记录每次调用 `(category, adapter, latency_ms, status, err)` 到 `data_fetch_log` 表，供 UI 审计与健康评分。

### 4.3 CircuitBreaker

沿用现有 3 态机（CLOSED / OPEN / HALF_OPEN）。参数集中到 `app_config` 表，运行时可调：
```
failure_threshold      = 5
success_threshold      = 2
reset_timeout_sec      = 300
failure_rate_threshold = 0.5
window_size            = 10
```

### 4.4 PriorityConfig（新增）

- 持久化到 Postgres 表 `data_source_config`（而非 JSON，和 Doc2 两个方案中选 DB 方案，和系统其它配置一致）。
- 提供：`load()` / `save()` / `move_up(category, adapter)` / `move_down(...)` / `toggle_enabled(...)` / `update_meta(...)`。
- `DataSourceManager` 启动时调用 `PriorityConfig.load()`，若表为空则写入 §2 默认链并返回。

表结构：
```sql
CREATE TABLE data_source_config (
    category     TEXT NOT NULL,
    adapter      TEXT NOT NULL,
    priority     SMALLINT NOT NULL,      -- 0 = 最高优先
    enabled      BOOLEAN NOT NULL DEFAULT TRUE,
    rate_limit   INT,                    -- requests / min
    timeout_sec  INT,
    max_retries  SMALLINT DEFAULT 2,
    metadata     JSONB,
    updated_at   TIMESTAMPTZ DEFAULT NOW(),
    PRIMARY KEY (category, adapter)
);
```

### 4.5 CacheManager（新增）

- 统一 Redis key 规约：`dg:{category}:{hash(params)}`。
- TTL 按品类表驱动（§2 缓存列）。
- `DAILY_KLINE` 特殊：不使用 Redis，直接命中 `kline_daily` 表 + 当日 `redis:incremental:{code}`。
- 提供 `invalidate(category, **params)` 给 UI 使用。

### 4.6 HealthChecker（新增）

- APScheduler 每 5 分钟一轮：对每个启用的 adapter 执行 `health_check()`，写入 `adapter_health` 表（timestamp, adapter, ok, latency_ms, err）。
- 连续 3 次失败 → 在 UI 上标红，但不自动禁用（禁用由 CB 控制或人工）。

## 5. 代理策略（关键）

### 5.1 问题
jd 的 `/etc/environment` 或用户 shell 设置了：
```
HTTP_PROXY=http://sg-proxy:xxxx
HTTPS_PROXY=http://sg-proxy:xxxx
```
用于访问境外服务。但 AKShare / Sina / 自研爬虫的目标是**国内**源（eastmoney、sina finance 等），走 SG 代理会：
- 绕一圈增加延迟；
- 代理出口 IP 若在海外，部分接口 403；
- 部分接口对出海 UA 触发风控。

### 5.2 解决方案 — `proxy_policy.py`

```python
# 原则：适配器自己决定是否用代理，不依赖环境变量。
import requests

def build_domestic_session() -> requests.Session:
    """国内源 adapter 专用：禁用环境代理，直连。"""
    s = requests.Session()
    s.trust_env = False          # 忽略 HTTP_PROXY / HTTPS_PROXY 环境变量
    s.proxies = {}               # 显式清空
    return s

def build_overseas_session() -> requests.Session:
    """预留：如需访问境外源（当前无）走系统代理。"""
    s = requests.Session()
    s.trust_env = True
    return s
```

**AKShare 的特殊处理**：AKShare 内部大量使用 `requests.get()`（不经过 Session）。三种落地方案，择一即可：

1. **首选**：monkeypatch `requests.api.request` / `requests.sessions.Session.merge_environment_settings`，在 adapter 进程启动时调用一次，强制 `trust_env=False`。
2. 备选：在进程级 `os.environ.pop("HTTP_PROXY", None)` / `HTTPS_PROXY` / `NO_PROXY=*`。由于整个后端就是为了调国内源，直接清掉环境变量最省事。
3. 若未来真需要境外访问，再在具体调用处显式 `requests.get(url, proxies={"https": SG_PROXY})`。

**推荐采用方案 2**：在 `backend/core/startup.py` 的最早位置：
```python
for k in ("HTTP_PROXY", "HTTPS_PROXY", "http_proxy", "https_proxy"):
    os.environ.pop(k, None)
os.environ["NO_PROXY"] = "*"
```
原因：本项目所有出站都是国内源，清干净最简单、最不易出错；未来真要用境外源再在 overseas adapter 内显式注入代理即可。

### 5.3 验证方法
部署后在 jd 执行：
```
python -c "import akshare as ak; print(ak.stock_zh_a_spot_em().head())"
```
应 < 2s 返回数据且无代理相关错误。

## 6. TuShare 降级与升级预案

### 6.1 当前 (120 积分)
- adapter `_supported_categories = {DAILY_KLINE}`。

## 8. 盘中 10s 快照（用户自研爬虫）

### 8.1 接口契约
用户在 `crawler_adapter.py` 内实现：
```python
class CrawlerAdapter(BaseDataAdapter):
    def get_intraday_snapshot(self, codes: list[str]) -> pd.DataFrame:
        """
        Returns: DataFrame[code, ts, price, volume, amount, bid1..5, ask1..5, ...]
        ts 必须是 UTC tz-aware datetime。
        """
```

### 8.2 调度
- APScheduler job `intraday_snapshot_job`，cron `*/10 * 9-11,13-15 * * mon-fri`（交易时段每 10s 触发）。
- 流程：拉取订阅池（默认龙虎榜中 T-20 日内出现过的 code 全集 + 今日涨停池） → `CrawlerAdapter.get_intraday_snapshot(codes)` → 批量 insert 到 `market_snapshots` hypertable → publish 到 Redis 频道 `snapshot:{code}` 供 WebSocket 推送。

### 8.3 降级
- 若单次 fetch 失败：CB 记一次失败，跳过本 tick，不阻塞下一轮。
- 若 CB 打开：APScheduler job 检测到 → 降级为 30s 一次，直到 CB 恢复。
